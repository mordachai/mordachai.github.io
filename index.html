How it's built

Same answers I'd give in a technical interview.

01

Vanilla JavaScript, ES modules. No framework: Foundry's own Application/Hooks API, Handlebars templates and scoped CSS. Larger packages are split into modules by concern — rolls, HUD, settings, NPC logic.

02

UI over an existing canvas. Most of these are interface work: HUDs and panels that sit on a PIXI canvas without fighting it, drag-and-drop on the scene, live sync between GM and player clients via socket events.

03

Data and content pipelines. Compendium packs (14 in Vagabond, 8 in Xeno Dead Zone), JSON mapping layers for art, importers that read an external web API and map it onto actor schemas.

04

Released like software. Semantic versions, tagged GitHub Releases with a manifest each, compatibility ranges declared per Foundry version, migration notes when a schema changes.

05

Maintained in public. Issues, feature requests and bug reports from real tables, plus localization (en / pt-BR) and documentation written for non-technical GMs.

Stack

JavaScript (ESM), Foundry VTT API, Handlebars, HTML/CSS, Git & GitHub Releases, JSON schemas, Babele localization, Unreal Engine 5, Blender, Substance, Photoshop, n8n / Make automation.
